## A. Executive summary

**Design direction.** Let speedcubers prepare, time and review their next OLL or PLL attempt using Timer’s visual hierarchy. The setup notation and clock lead. Statistics and history belong in the left rail, and completed-case feedback belongs in Last Result.

1. **Fix parity at the rendered boundary.** E14 reused the Statistics and History shells, metric columns, history row, split and TimerStage. Training still gives the same components a taller, mode-dependent rail, extra controls inside Statistics, a button as the whole timing row and a case label where Solves uses a timestamp plus scramble. Reuse the same row geometry, budget and focus rules alongside the same components.
2. **Make the timer position a workspace constraint.** Training’s preparation header grows and shrinks with the preview, recognition prose, stop line and calibration sample review. The remaining flex height then determines the timer centre. Keep one compact setup region across ordinary states and give review, errors and calibration controls their own deliberate placement.
3. **Reduce routine copy and competing actions.** Replace the verified count with selected cases, concentrate setup progression in one action, show the exact recognition precursor and surface calibration or eligibility problems when action is needed. Keep help available by touch and keyboard.
4. **Add a local, default-on “Show upcoming case” preference.** One preference covers OLL and PLL execution. The rendering boundary must exclude upcoming case identity entirely when preview is off or recognition is active. Last Result reads the previous completed attempt only.
5. **Address correctness in the relevant slices.** A known-case retry can silently switch the category. Calibration announces a recorded result before sample acceptance. Deferred generation can leave a spinner stuck or restore a setup after visit expiry. A checked-save retry can publish preferences out of step with the runtime category. The report action’s label overpromises its destination. Capture these paths before changing their owners.

The blueprint retains the four independent category histories, checked local persistence, 78 approved diagrams, existing timing and math, and the seven-sample protocol. The “Stage 1–5” labels below describe redesign delivery slices. Project Training Phase 5 is outside this assignment.

## E. UI text and information density

Training's job is to let speedcubers choose OLL or PLL cases, apply the setup, time an attempt, and quickly review the result. The workspace should read in that order. The following inventory groups repeated strings, generated labels, and values by owner. Placeholders in angle brackets represent values such as counts, case names, or formatted times. User-entered algorithm notation and preset names remain as entered. Mobile uses the same copy and a different layout, so the inventory calls out mobile placement and accessibility where they differ.

Rendered examples show the repeated mode and verified count in execution and recognition, the two-line Attempts row, and the calibration sample actions. At 320 px the settings renewal policy wraps to seven lines and pushes the Save action to the bottom of the visible dialog.
